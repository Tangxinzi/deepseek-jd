# DeepSeek JD Writer

一个用于中文职位描述（JD）和团队使命写作的 Codex Skill。它学习的是 DeepSeek 示例背后的写作决策，而不是复制原文：让使命有人真实关心的处境、有技术细节、有明确的未完成问题，也让候选人看见自己可以承担的真实工作。

更多查看 👉👉👉 [AI × HR 应用实践](https://my.feishu.cn/docx/PaASdKSVFoKFsXxF3mvcukTAnRc)。

## 快速使用

在 Codex 中直接调用：

```text
$deepseek-jd
请为我们的推理基础设施团队写一份后端工程师 JD。
团队负责降低在线推理延迟，服务对象是内部模型和产品团队。
```

也可以把 Skill 名称放在自然语言中：

```text
用 deepseek-jd 改写下面这段团队使命，保留事实，增强使命感：
……
```

如果请求已经明确属于 JD 或团队使命写作，Skill 也可以被自动识别。首次使用时，尽量提供团队事实；信息不足时，Skill 会标注假设或提出少量关键问题，不会自行补写规模、技术、用户或福利承诺。

## 安装

将仓库克隆到 Codex 的用户级 Skill 目录：

```bash
git clone https://github.com/Tangxinzi/deepseek-jd ~/.codex/skills/deepseek-jd
```

安装后可直接调用 `$deepseek-jd`；如果目录已存在，更新时在该目录运行 `git pull`。

### 只发岗位名

显式调用后只输入岗位名（例如“产品经理”），Skill 会直接给出一版精简岗位建议，不展示分析过程，也不会先让你补充资料。公司、产品和用户信息未知时，文案会保持中性，避免虚构具体事实。

正文结尾会保留一个简短的有用收尾：有具体改进空间时用 `【建议】` 给出 1-3 条建议；没有独立建议时用 `【下一步】` 指出最值得补充的信息或可继续生成的版本。

### JD 的视觉区块

完整 JD 会放在一个独立的纯文本区块中；在对话里，`text` 区块只承担视觉分隔作用。区块内使用可直接粘贴到发布表单的纯文本，不使用 Markdown 标题、加粗、项目符号、表格、链接或其它 Markdown 语法；用 `【团队使命】`、`【工作职责】`、`【核心要求】` 等标签分段，条目使用 `1、` 而不是 Markdown 编号。`【建议】` 或 `【下一步】` 会放在区块外。

## 支持的模式

- **完整 JD**：团队使命、岗位概述、职责、核心要求、加分项和招聘方向。
- **只写使命**：只输出团队使命，并简要列出采用的事实假设。
- **使命点评**：先说明现有文案为何有效或失效，再给出针对性改写。
- **岗位适配**：保留共同使命，为不同职能或职级改写职责和能力证据。
- **多版本**：输出 2-3 个语气不同的使命版本，并标注语气取向。

不确定模式时，Skill 会选择最小满足方案；要求“只写使命”时不会展开成完整 JD。显式调用且只给岗位名时，按“直接输出”快捷规则处理，并以 `【建议】` 或 `【下一步】` 收尾。

## 建议提供的信息

信息越具体，使命越有力量。可以按以下顺序提供：

1. 团队正在改变、建设、衡量或保护什么。
2. 谁会因此变得更有能力、更安全、更高效或更自由。
3. 为什么现在必须做，以及真正的瓶颈、风险或取舍。
4. 团队能控制的系统、数据、用户、约束和交付物。
5. 岗位的职能、职级、地点、技术栈，以及可验证的能力证据。
6. 已确认的事实、待确认的假设，以及明确不能出现的说法。

可以只给一段粗略背景；如果关键事实缺失，Skill 会先把需要补齐的内容说清楚。

## 写作方法

使命通常沿着这条路径展开：

```text
更大的现实 -> stakes -> 具体前沿问题 -> 团队能做什么 -> 对合适候选人的邀请
```

开头先提出一个可记住的使命论点，例如“X 是 Y 的基石”或“我们不只是 X，更是在让 Y 成为可能”；随后必须用真实系统、用户、约束和失败模式证明它。情绪来自 stakes、specificity 和 agency 的相乘，而不是来自“顶尖”“改变世界”等形容词。

默认使用平衡语气，也可以指定：

- **史诗感**：适合时代变化、基础设施和长期建设。
- **技术感**：突出架构、性能、可靠性和取舍。
- **人文感**：突出用户、知识、关系与人的能力。
- **克制感**：少修辞，强事实，适合专业和运营岗位。

## 输出约定

完整 JD 通常包含：

```text
【职位名称】
产品经理

团队/职能：……
地点：……
工作性质：……

【团队使命】
【岗位类别】
【招聘方向】（如适用）
【工作职责】
【核心要求】
【加分项】（如适用）
```

职责写成结果和影响对象，要求写成可观察的能力证据。福利、投递按钮、面试流程和口号不混入团队使命，除非用户明确要求。

输出时将以下内容整体放入一个 `text` 区块：

```text
【职位名称】
产品经理

团队/职能：……
地点：……
工作性质：……

【团队使命】
……

【工作职责】
……

【核心要求】
……
```

区块外只放简短的建议或下一步引导，不放写作过程、假设说明或重复 JD。

建议不只针对文案，也可以提示发布前补齐信息，例如薪酬范围与结构、工作地点与办公方式、福利待遇、用工性质、职级、汇报对象、招聘人数、到岗时间、投递方式和招聘流程等。只提示当前确实缺少且有价值的 1-3 项，不把未知内容写成事实。

## 维护与校验

修改 `SKILL.md`、参考文档或界面元数据后，运行：

```bash
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py \
  ~/.codex/skills/deepseek-jd
```

校验通过只说明目录结构、命名和元数据有效；实际质量仍应通过真实 JD 请求进行前向测试，重点检查是否保留事实、是否把使命落到具体工作，以及是否出现未经确认的夸大承诺。
